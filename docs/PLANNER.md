# 组卷规划器

`planWorksheet(catalog, options, dependencies?)` 与 `summarizeAvailability(...)` 位于 `src/planner.js`。第三参数用于注入真实引擎或契约测试依赖。

## 先规划，再选题

- **custom**：只有一个严格分区，只用指定等级，不暗降级。
- **daily / thinking**：先按题量分配分区。12题为4/4/2/2，6题为2/2/1/1，18题为6/6/3/3。首区用L1，主区用不高于上限的L2，后两区使用选定上限；上限为1时全部L1。页面明确混合等级政策。
- 每个槽位先限制等级、年级、学期、知识点及维度，再依据知识点/维度/家族累计次数和相邻家族、表示/推理角色评分。候选多的知识点不能仅因池大而垄断整卷。分区不是抽完题之后随意贴标签。
- 选择顺序可复现。同答案连续3次后，存在合规替代项时改选其他答案；硬约束无法兼顾时给质量警告，不伪造多样性。
- `sections.questionIds` 对应实际返回题目。缺槽位如实写入 `quality.deficits`；不重复、扩大范围或改级填满。

## 去重与容量

共享 `questionDedupKey` 处理题目身份。精确二元算式结果题与作者明确声明的相同最终结果任务可跨来源、数字遮罩外的措辞和可选图示去重，例如“计算9＋5＝？”与“9＋5＝□”。保留操作数顺序。多小问、分解、解释、选择和不同未知位置不混为同一个要求。

这是有边界的数学任务规范化，**不是任意自然语言语义理解**。无法识别的题使用完整题干/作答内容的字面身份；不以更换数字就宣称增加结构家族。

`generateCandidates` 可以保留来自多个家族的字面候选，容量统计与最终选择则使用共享数学任务身份。`availableCount` 是当前种子下有界候选的去重并集，不是无限数学题量，也不是各等级/维度计数相加。报告逐等级、逐维度数量及家族数。总容量不单独保证特定教学配额可行，最终还须看分区缺口和质量警告。

## 历史错题

`remediation` 默认只回看保存的原题，不重新随机生成，不从一次错误诊断能力。每卷遵守请求题数；超出的历史记录保留并提示，不删除错题本。只有显式 `addRelated: true` 才在明确选择的范围内补充相关新题。

旧记录的修订、来源和原始题目保留。渲染/评分适配层可以应用已登记的源答案纠正；这不等于改写保存的原记录或把来源修订伪装成新原始数据。因范围问题退出新题池的历史题不会因此自动从用户历史中删除。

## 验证

`tests/planner.test.js` 验证范围、等级、配额、实际题号、确定性、池大小偏差、容量并集和历史保留；`tests/backend-regressions.test.js` 覆盖跨来源/任务家族的同一道9＋5及保留真实不同作答要求。全套结果见 `VERIFICATION.md`。这些策略没有经过学生样本标定，不构成自适应测评系统。
